# 沟通管理

## 业务概述

本系统为婚恋社交平台的沟通管理模块，负责红娘牵线、用户沟通、群组聊天等核心业务功能。核心流程为：红娘发起牵线申请 → 用户确认同意 → 建立沟通会话 → 创建群组 → 开始沟通交流。

## 角色定义

### 普通用户
- 接受红娘牵线，与其他普通用户建立沟通关系
- 可以接受或拒绝牵线申请
- 参与群组沟通

### 红娘用户
- 发起牵线申请，为普通用户配对
- 需要竞争上岗，获得双方用户同意后正式担任牵线红娘
- 可以选择辅助红娘协助工作
- 参与群组沟通和策略讨论

## 功能模块

1. **牵线申请**：红娘选择用户发起牵线申请
2. **申请确认**：用户确认接受或拒绝牵线
3. **沟通会话管理**：创建、管理沟通会话
4. **群组管理**：创建大群和红娘对策群
5. **消息管理**：发送、接收消息
6. **通知管理**：发送牵线邀请、状态变更等通知

## 注意事项

1. **并发控制**：牵线申请的双方确认状态需考虑并发问题，避免同时操作导致状态不一致
2. **数据一致性**：牵线申请状态变更时，需同步更新沟通会话状态
3. **消息顺序**：消息表需按发送时间排序，确保消息顺序正确
4. **通知及时性**：关键业务操作（如牵线确认、消息发送）需及时发送通知
5. **权限控制**：用户只能查看和发送所属群组的消息
6. **数据归档**：已结束的会话和历史消息可考虑归档处理，优化查询性能

**通知内容规则**：

### 3. 邀请管理菜单（待开发）

**界面位置**：HeaderBar 右上角用户下拉菜单中，"我的"选项下方

**可见性**：所有角色（红娘 + 普通用户）都能看到

**界面内容**：
点击"邀请管理"菜单项，弹出列表面板，展示当前用户相关的所有牵线邀请：

**列表项结构**：
```
邀请日期 | 红娘姓名
用户A头像 用户A姓名 [用户A确认状态] - [连线] - [用户B确认状态] 用户B头像 用户B姓名
[接受邀请]  [拒绝邀请]
```

**状态显示规则**：
- 每个用户的确认状态显示在各自头像下方（不在连线中间）
- 初始状态：用户A、用户B头像和名字均为灰色，头像下方显示"待确认"
- 用户A确认后：用户A头像和名字恢复彩色/黑色，头像下方显示"已接受"
- 用户B确认后：用户B头像和名字恢复彩色/黑色，头像下方显示"已接受"
- 双方都确认后：头像下方的状态标签隐藏，连线上方显示"双方已接受"
- **拒绝流程特殊规则**：
  - 当一方（如A）点击拒绝时，另一方（B）**看不到**A的拒绝状态，B仍然看到A显示"待确认"，B仍可正常操作（接受或拒绝）
  - 红娘（管理员）**始终可以看到**双方的真实状态（包括已拒绝）
  - 只有当**双方都完成操作**后，才能看到对方的状态
  - 双方都操作后的两种可能状态：
    - "双方意见不一"：一方接受、一方拒绝 → 连线变红色，连线上方显示"双方意见不一"
    - "双方已拒绝"：双方都拒绝 → 连线变红色，连线上方显示"双方已拒绝"
- 连线颜色：双方都确认后变绿色；任一方拒绝或双方意见不一时变红色；否则灰色
- **底部状态标签：完全移除，不再显示**

**交互功能**：
- 点击任意用户头像，弹出用户信息小框（所有角色均可查看匹配对象的信息）
- 红娘在该页面中无任何操作按钮，仅查看
- 被邀请用户可以在列表中点击"接受"或"拒绝"按钮：
  - 点击"接受"：更新状态，发送通知给红娘
  - 点击"拒绝"：更新状态，发送通知给红娘
  - 已接受/已拒绝的邀请，按钮变为禁用状态

**可见范围**：
- 红娘：只能看到自己发起的邀请
- 普通用户：只能看到自己被邀请的匹配

**红娘名称显示**：
- 红娘名称必须从 expand 数据中正确获取，显示为实际的红娘姓名/用户名/邮箱
- 禁止显示为"红娘：红娘"这种 fallback 值

#### 8.6 数据存储

**使用 SQLite（PocketBase）存储聊天记录**：

- 消息表：`messages`（已在 schema.sql 中定义）
- 存储方式：**一条记录存储一条消息**，通过 `group_id` 关联会话
- 理由：
  - 可查询、可分页、支持索引
  - PocketBase 原生支持
  - 2 核 2G 40G 服务器完全够用
  - schema.sql 中已定义好表结构

**消息记录字段**（对应 messages 表）：
- `group_id`：所属群组ID
- `sender_id`：发送者ID
- `message_type`：消息类型（0-文本，1-图片，2-语音，3-视频，4-文件）
- `content`：消息内容（文本消息时使用）
- `file_url`：文件/图片URL
- `duration`：语音/视频时长
- `is_read`：是否已读
- `send_time`：发送时间

#### 8.7 沟通会话与群组自动创建

**触发条件**：邀请管理中双方都接受邀请后（`application_status = 1`）

**自动创建流程**：
1. 创建 `communication_sessions` 记录
2. 创建大群（`chat_groups`，`group_type=0`，群名格式：`{userA姓名}与{userB姓名}的沟通群`）
3. 创建红娘对策群（`chat_groups`，`group_type=1`，群名格式：`{红娘姓名}的对策群`）
4. 添加群成员（`chat_group_members`）：
   - 大群：红娘（群主）+ 用户A + 用户B
   - 对策群：红娘（群主）+ 辅助红娘（如有）
5. 发送通知给相关用户："您已被邀请加入沟通群"
